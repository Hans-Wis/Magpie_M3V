**Date:** June 8, 2026

## 1. Executive Summary
The RTL is highly consistent and follows a well-defined architectural pattern (4-stage pipeline with variable-latency memory support). The use of `def.vh` ensures constant consistency across opcode and control encodings. The primary findings relate to potential metastability in the external IRQ path and slight deviations in the Register File reset strategy.

## 3. Detailed Review

### 3.1 Reset Convention Consistency
- **Standard:** All modules (except RFU) use **active-low synchronous reset** (`resetn`) triggered by `posedge clk`.
- **Deviation:** `rfu.v` relies on an `initial` block for simulation/FPGA power-on state. This is a mismatch with the core's general policy of explicit hardware resets for all architectural registers.

### 3.2 Signal Naming Consistency
- **High Consistency:** `stall`, `flush`, `valid`, and `redirect` are used with identical semantics across `core.v`, `ifu.v`, and `hazard.v`.
- **Memory Freeze:** `mem_stall` is correctly propagated from the `cpu_m1_top` wrapper to the core, implementing the **ADR-0005** freeze policy consistently across all pipeline stages.

### 3.3 X-Propagation Sources
- **Risk Mitigation:** Most `always @*` blocks (ALU, IDU, LSU, CSR) include `default` assignments or exhaustive `case` coverage to prevent latches and X-prop.
- **Observability:** `trap` is latched in `core.v` to ensure synchronous exceptions are stable for the wrapper to observe even if the internal signal pulse is narrow.

### 3.4 Clock & CDC
- **Single Domain:** The design is strictly single-clock (`clk`).
- **External Signals:** `irq_external_pulse` is the only cross-domain candidate. The implementation assumes it is already a synchronous pulse. If this comes from a button or external pin, a 2-flip-flop synchronizer is required.

### 3.5 Pipeline Register Conventions
- **Freeze Policy:** `EX/MEM` and `EX/WB` stages correctly implement the `mem_stall` hold condition.
- **Forwarding:** `forward.v` correctly prioritizes `EX/MEM` (closest) over `EX/WB` (further). It correctly prevents forwarding from `EX/MEM` for `is_load` instructions since the data is not yet available in that cycle.
