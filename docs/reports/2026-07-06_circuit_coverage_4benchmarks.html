04

兩個效率注意點(非阻塞)

電路都支援;這兩點是「支援但需注意」——一個微架構利用率、一個 kernel 策略紀律。

◆ 利用率

Depthwise = ⅛ MAC 利用率

depthwise 以 block-diagonal conv 映到 mat_engine:把 per-channel kernel 攤成 channel-masked 權重,精確 depthwise 累加從既有 im2col GEMM 落出(歸零 off-channel taps 恰貢獻 0)。已 RTL bit-exact(gate_82)。

代價:8×8 陣列每次只用對角,約 1/8 利用率。功能與正確性零妥協;拉高利用率屬未來 mat_engine 微架構優化,非缺電路。影響 MobileNet / MLPerf DS-CNN / VWW。

▲ 唯一 🟥 風險 + 已驗證避開法

LLM activation:走向量多項式,別走 LUT

本電路 無 indexed-load(vluxei=0)、vrgather 限 m1(≤16 lane)。故 256-entry activation LUT 無法向量 gather → 每元素 scalar lw = O(N) 序列 → softmax/gelu/silu 這種高頻逐元素會落 🟥。

避開法(全向量,op 全已證): gelu / silu / exp 改用 fixed-point 多項式——Horner vmul·vmacc·vadd + range-reduction vsra·vand,對整條向量 O(degree) 向量指令。所需 op 由 gate_62/66/68 + vrand 1324c bit-exact 證過 → activation 全向量,零 scalar 瓶頸。

誠實界

  • primitive 層級電路已全數硬證(mat_engine GEMM+requant、全 Zve32x op、scalar-F fsqrt/fdiv、pooling/DMA)。本報告是覆蓋對應證明——每個熱點 primitive 都有已證的硬體路。
  • 尚未實作完整 LLM/CNN kernel 的 firmware 組合(softmax / gelu-poly / RMSNorm / attention)——但用的都是已證 op,屬 kernel 軟體工作,非缺電路。MobileNet block 已 e2e 實證(gate_82);LLM 之 GeGLU foundation golden 已驗(ADR-0062)。
  • 模型維度取自公開資料(環境無 torch/transformers/HF)。決定電路支援的是 op 集(已確立),非確切維度;數值 e2e 用結構等價 + random 權重(同 MobileNet 做法)。
  • 與 Coral Kelvin 同級:同為 Zve32x-int 向量 + MAC 陣列 + scalar-F,同樣無向量超越函數硬體、同樣用整數 activation + scalar 輔助。凡 Coral 做得到的本電路亦然。
  • 非電路的真限制 = 系統:32KB DTCM 裝不下 LLM 權重,權重/KV 必經 DMA streaming(頻寬綁定)——這是記憶體/系統議題,與向量/矩陣 datapath 充分性無關。
