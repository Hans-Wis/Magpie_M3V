Magpie-M3V · 自建 RV32 NPU · 功能取代 Google Coral (Kelvin)

Magpie-M3V RV-NPU 設計規格與加速架構

Magpie-M3V 是一顆自建、可用標準開源工具鏈編譯的 RV32 NPU IP，目標為功能取代 Google Coral NPU（同一 TFLM int8 workload bit-exact 可跑）。本規格書在原 RV32+RVV 參考架構之上，補充 Gemma-3 效能分析與本線自建的 mat-engine 硬體加速 （v2 tile sequencer + activation-stationary，實測 5.5×，附架構圖解）。所有效能數字皆於 RTL 實測、對 bit-accurate golden 逐位驗證；面積/功耗來自真 28 nm 合成流程。

RV32IMF + Zve32x (完整) 256-MAC 矩陣引擎 + 硬體 tile sequencer GEMM offload 實測 5.5× LANES SKU · 64 / 128 / 256 MAC bit-exact vs golden TSMC 28nm PPA
01

設計目標與範疇

此核心目標為在穿戴式裝置（耳機、AR 眼鏡、智慧手錶）等超低功耗場景下，提供一顆 「可用標準工具鏈編譯、又具備 ML 推論所需資料路徑效率」的 C-programmable 加速器， 在通用可程式性與領域專用效率之間取得平衡（此為 Coral NPU 的核心設計哲學）。

設計目標

  • 能效優先：降低純量控制流的 overhead，並縮短資料在記憶體階層中的搬移距離。
  • 標準工具鏈相容：以 RISC-V 標準擴充（I/M/F/Zve32x/Zicsr/Zifencei/Zbb）為基礎，可用 GCC/LLVM 直接編譯 C/C++。
  • 向量化 ML 運算：透過 RVV（Zve32x）子集提供 8/16/32-bit 資料寬度的 SIMD 運算，滿足 int8/int16 量化推論需求。
  • 可整合性：以 AXI4 作為 SoC 週邊介面（同時具備 master 與 slave 角色），可被外部 host CPU 配置與除錯（GDB）。
  • 確定性延遲：ITCM / DTCM 採用 single-cycle SRAM 而非快取，避免快取失誤造成的不確定延遲。
Claude Code 實作原則 實作時請將「純量核心 (scalar)」「向量核心 (rvv)」「矩陣核心 (matrix，選配)」視為三個可獨立驗證的子系統， 透過明確定義的 command queue / scoreboard 介面耦合，而非緊密糾纏的單一大型模組。任何新增指令或資料通路， 都應先更新本規格書對應章節，再落地為程式碼與測試。

暫存器檔案

純量暫存器

31 個 32-bit 通用暫存器 x1–x31，x0 硬接地為 0。位址空間 32-bit，適用於應用程式與作業系統核心。

向量暫存器

32 個 256-bit 向量暫存器 v0–v31，支援 8/16/32-bit 元素寬度切分（例如 int32 × 8 lane）。

純量 ISA 為 RV32IMF（scalar F 全套已上線，ADR-0050）；向量資料型別 int8 / int16 / int32 （int32 累加）。向量走標準 RVV Zve32x（完整，非自訂指令）——刻意與開源 clang-RVV + TFLM 對齊，讓標準工具鏈可 drop-in；矩陣卸載經 command queue / 硬體 tile sequencer（見 §16），非自訂 ISA。

04

管線微架構

四級管線（Fetch / Decode / Execute / Writeback），單發、依序（single-issue, in-order）。 多週期單元（Mul-Div / FPU / 除法）以 stall 保持依序完成；向量指令於 in-core 向量單元 vexu 執行（非獨立分派流），矩陣運算經 command queue / 硬體 tile sequencer 卸載（見 §16）。NPU sequencer 為此 spine 的 stripped run-to-completion 版本。

圖 4.1 — 四級管線示意圖（單發、依序;純量 / 向量(vexu) / 訪存為功能單元）

Hazard 與流程控制

  • 單發依序管線主要 hazard 為 RAW（以 forwarding 解）、load-use 與多週期單元（Mul/Div/FPU）以 stall 保持依序。
  • Pipeline stall / flush 機制需支援分支誤判、例外 / 中斷進入時的管線清空。
  • 多週期單元（div / FP）與 LSU（純量 / 向量共用資源）完成需回饋管線;向量（vexu）與純量共用同一 issue 前端。
Claude Code 實作原則 Scoreboard 與 dispatch 邏輯應設計為獨立、可單元測試的模組（見第 12 章佈局），並針對 RAW/WAR/WAW 三類情境各自撰寫方向性測試（directed test）與隨機測試（random test）， 避免僅以整合測試覆蓋 hazard 邏輯。

未支援指令會被編出來卡住嗎？（客戶關切）

誠實面對：若以完整 -march=…zve32x 編譯而硬體只實作子集，編譯器 確實可能 emit 未支援指令（尤其 gather / scatter 存取樣式或手寫 intrinsic）——Zve32x 無標準 「排除 strided」子 profile，故無法僅靠 -march 讓編譯器只用子集。保證不是 「編譯器不會 emit」，而是下列三層防護讓它「絕不會卡死、且可攔在部署前」：

子集 ISA 的三層防護
層機制效果現況
1 · Build-time 攔截
（主要保證）		 編譯後對 binary 做 opcode 白名單掃描（objdump / disasm ingester），任何子集外指令 build 即 fail 客戶部署前就知道；絕不會出貨會 trap 的 binary（把 runtime 風險變成 build error） 本線已有 isa_cov opcode ingester，可直接做成 build gate（推薦入交付 flow）
2 · 乾淨 trap
（不是 hang）		 NPU sequencer 有 trap handler（crt 設 mtvec）→ 非法指令 mcause=2 → latch ERR_PC / ERR_CAUSE → IRQ 回 host 萬一漏網也是可觀測的錯誤回報，不是無窮迴圈卡死；host 收到 ERR_CAUSE 可 abort / 換手 ✅ 已實作（ADR-0038 trap-to-host）
3 · Trap-and-emulate
（可選,100% 相容）		 trap handler 以純量軟體模擬該指令（同 FPU 模擬慣例），resume 續跑 程式正確跑完（較慢）而非失敗——若客戶要求任意 Zve32x binary 皆可跑 可選,未實作（架構上支援）
實務背書 目標 workload（TFLM int8 推論,對標 Coral）實測不觸及缺口：clang/gcc auto-vectorization 對標準 kernel 只 emit unit-stride + 已支援運算；strided/indexed 樣式（depthwise、im2col、stride-2 conv）由 mat_engine + 2D/strided DMA 在 offload 層處理，不進 RVV datapath。實測 MobileNet / MLPerf Tiny / Gemma-3 e2e 皆零 strided/indexed RVV 即 bit-exact。
→ 故「Coral Zve32x 計算程式 drop-in」可取代性成立；缺口為記憶體定址模式（非計算能力），且由三層防護 保證「build 攔 + 乾淨 trap + 可選 emulate」，客戶不會遇到硬體卡死。
07

矩陣執行引擎（mat-engine）

量化外積乘加（outer-product MAC）引擎，加速 GEMM 密集之 ML 運算（卷積、全連接、attention）。 MAC 陣列寬度為 synth-time 參數 LANES∈{1,2,4} → 64 / 128 / 256 MAC， 讓客戶按 workload 選面積/功耗檔位（PPA 見下表）。其硬體 tile sequencer 加速見 §16。

運算模式Quantized outer-product MAC（8×8 tile,一拍一 outer product）
MAC 陣列64 / 128 / 256 MAC/cyc（LANES=1/2/4;K-fusion 寬度可配置）
累加 / requant4 banks × 8×8 × int32 acc · TFLite/gemmlowp 兩步 requant（bit-exact）
卸載控制command queue + 硬體 tile sequencer（npu_ml_ctrl,§16）
資料型別int8 乘 · int32 累加

MAC 陣列 SKU — PPA（真 TSMC 28nm 合成,同時脈皆達 timing）

Measured · design decision 面積/功耗不隨 MAC 數線性下降（256→64 為 4× 少 MAC 但面積僅 −40%）——因 acc-bank + requant datapath + FSM 為 LANES-independent 固定成本,只有 MAC 乘法樹隨 LANES 縮。邊緣推論（batch-1 decode）多 頻寬綁定,64-MAC 幾乎不掉速卻省 −40% 面積 / −43% 功耗,故對標 Coral 有面積/功耗優勢; prefill / batch 大則選 256。三檔皆 bit-exact（整數累加可結合,同一 golden 驗證）。

08

記憶體子系統

採 tightly-coupled memory（TCM）而非快取，確保單週期存取延遲與可預測時序， 適合即時性要求高的推論工作負載。

圖 8.1 — 記憶體階層與存取路徑

  • ITCM 與 DTCM 皆為單週期延遲 SRAM，效率優於快取記憶體（無 miss penalty）。
  • LSU 透過 IBUS / DBUS / EBUS 三組匯流排存取 ITCM、DTCM 與外部記憶體。
  • 支援 byte / half-word / word 三種資料存取粒度，以及多種 burst 模式與長度。
  • 需正確處理 WRESP（write response）與 RDATA（read data）之 back-pressure。
09

AXI4 匯流排介面

核心以 AXI4（AMBA 標準）作為對外週邊介面，同時扮演 master（存取外部記憶體）與 slave（供 host 處理器配置 / 除錯核心）角色。

AXI4 通道
AWWrite address channel
WWrite data channel
BWrite response channel
ARRead address channel
RRead data channel
  • 需支援位址合法性與對齊（address validity / alignment）檢查。
  • 需支援 ready/valid 交握協定與 INCR / FIXED burst 交易模式。
  • 需具備錯誤訊號回報（error signaling）機制。
  • 作為 slave 時，需支援 host 透過 AXI4 讀寫本核心之自訂 CSR（見第 10 章）。
10

CSR 規格

除標準 RISC-V Zicsr CSR 外，核心額外定義三個自訂 CSR，供外部 host 處理器透過 AXI4 slave 介面存取， 用於核心重置、啟動位址設定與狀態查詢。

自訂 CSR：RESET_CONTROL（offset 0x0）
Bits名稱說明存取重置值
0RESET1 = 核心處於 reset 狀態；0 = 非 resetR/W1
1CLOCK_GATE1 = 時脈閘控中；0 = 時脈運行中R/W1
31:2RESERVED保留，寫入忽略，讀取為 0R0

啟動順序：上電後核心處於 reset 且時脈閘控。啟動流程須先釋放 CLOCK_GATE， 再解除 RESET。

自訂 CSR：PC_START（offset 0x4）
Bits名稱說明存取重置值
31:0START_ADDRESS核心開始執行的位址。須於解除 reset 前設定。R/W0
自訂 CSR：STATUS（offset 0x8，唯讀）
Bits名稱說明存取重置值
0HALTED1 = 核心已停止（例如執行 mpause 後）R0
1FAULT1 = 核心發生錯誤R0
31:2RESERVED保留，讀取為 0R0

標準 RISC-V CSR（Zicsr）

  • 每個 hart 擁有獨立位址空間，最多 4096 個暫存器。
  • CSR 位址高 4 位元 csr[11:8] 依慣例編碼讀寫權限與最低可存取特權等級。
  • 特權架構相關 CSR 供作業系統 / hypervisor 管理系統、處理中斷、控制硬體功能；非特權指令則可存取效能計數器、計時器、浮點狀態暫存器等子集。
11

例外與中斷處理

  • 需實作例外偵測與處理流程：進入 / 返回序列、cause 記錄、優先權排序。
  • 純量核心負責中斷之接收與分派；向量 / 矩陣引擎之運算錯誤需回報至純量核心的例外邏輯。
  • 建議 cause 編碼遵循 RISC-V Privileged 規範，並保留自訂錯誤碼區段供向量 / 矩陣引擎專用例外使用。

命名與模組邊界原則

  • 純量 / 向量 / 矩陣三引擎各自為獨立 Verilog 模組（分別置於 rtl/scalar、rtl/vector、rtl/matrix），僅透過 command queue 或 scoreboard 明確介面通訊，禁止跨模組直接存取內部訊號。
  • rtl/soc 僅負責頂層接線與仲裁，不得放入任何運算邏輯，以維持三引擎的獨立驗證性。
  • 自訂 CSR（RESET_CONTROL / PC_START / STATUS）獨立於標準 Zicsr CSR file，並在頂層文件中明確標示其為「非 RISC-V 標準暫存器」。
  • 任何新增的自訂指令 / CSR，需同步更新本規格書第 02、10 章與對應測試計畫。
  • lint/ 內的 waiver 清單需附上理由註解，不得無說明地全域關閉規則。

驗證策略

純量核心驗證

RV32IM 指令逐一方向性測試、CSR 讀寫測試、分支 / 跳躍正確性、hazard（RAW/WAR/WAW）方向性 + 隨機測試。

向量核心驗證

依 SEW（8/16/32）分別驗證資料切分正確性、累加器溢位處理、command queue 與純量前端之交握時序。

匯流排 / 整合驗證

AXI4 master/slave 各通道之 handshake、burst、error signaling；host 透過 slave 介面存取自訂 CSR 之流程。

系統層級驗證

以 GDB 連線驗證除錯流程；以代表性 ML kernel（如 int8 卷積、姿態估測子運算）驗證端到端功能與效能。

Claude Code 實作原則 每完成一個模組（scalar / rvv / bus / csr），先撰寫對應 cocotb 測試並確認通過，再進入下一模組； 避免在缺乏單元測試覆蓋的情況下進行大範圍整合。所有測試需可於 CI 中重現執行。

建議實作里程碑

  1. M1 — RV32IM 純量核心：fetch/decode/dispatch、ALU/BRU/Mul-Div、暫存器檔、基本 CSR，通過 RV32IM 指令集測試。
  2. M2 — 記憶體與匯流排：ITCM/DTCM 整合、LSU、AXI4 master/slave，通過匯流排整合測試與自訂 CSR 存取測試。
  3. M3 — F 擴充與 Zicsr/Zifencei/Zbb：補齊浮點運算與其餘標準擴充。
  4. M4 — RVV（Zve32x）向量核心：向量暫存器檔、SIMD ALU、command queue 介接純量前端。
  5. M5 — 矩陣引擎（選配）：依應用需求決定是否導入，並驗證與向量核心的資料共用路徑。
  6. M6 — 系統驗證：GDB 除錯流程、代表性 ML 模型端到端驗證、功耗與時序 sign-off。
  7. M7 — Benchmark 驗收：依序跑通 MobileNet → MLPerf Tiny → Gemma 3 270M → SmolLM2 135M，記錄各項功能性 pass/fail 與效能數據（cycles、tokens/sec）作為最終驗收基準。

Gemma-3 效能分析

以一個 Gemma-3 decoder layer（int8，代表尺寸 seq=4 / hidden=64 / ffn=128）在真 RTL 上實測 per-step cycle，定位瓶頸。關鍵結論：瓶頸不在計算，而在純量核心的 per-tile 編排—— 256-MAC 陣列真正 busy 僅 0.29% wall-clock，加 MAC 無用；真正該攻的是韌體開銷（見 §16 加速架構）。

16

mat-engine 加速架構（v2）

§15 定位出瓶頸 = GEMM 的 per-tile 韌體編排稅。Magpie-M3V 的加速策略是凍結 MAC 數學、 在其前面加一層硬體控制殼（npu_ml_ctrl），把整個 GEMM 的 tile 迴圈搬進硬體： 韌體只發一個 job，硬體自己走 tile、直接驅動 mat-engine 與 DMA，tile 間不回韌體。 q_proj 實測 13,350 → 2,425 cycle（5.5×），逼近記憶體頻寬地板。

加速原理 — 韌體逐 tile 序列 → 硬體 job 展開

圖 16.1 — 加速原理：韌體逐 tile CSR+spin-poll（~1,120 cyc/tile）→ 一個 job kick + 硬體展開（~24 cyc/tile）

控制殼架構 — 凍結 datapath + mux 進既有訊號

npu_ml_ctrl 自持 job CSR + tile FSM，其驅動的 mat/dma 訊號經一組 2-to-1 mux 疊在既有韌體 CSR 路之前；ML_V2_EN=0（預設）時 mux 恆選韌體路， 零回歸。mat-engine / DMA / CSR block 內部完全不改。

圖 16.2 — v2 控制殼：npu_ml_ctrl mux 進既有 mat/dma 訊號，datapath 凍結、預設走韌體路零回歸

資料佈局優化（Phase B）— 消冗餘 DMA

Phase A 消掉編排稅後，新瓶頸變成 DMA（80%）。Phase B 進一步優化 TCM 佈局： B1 activation-stationary（同一輸入不再逐 tile 重載，載一次常駐）+ B1.1 header-trim（去 blob padding、MAT_OUT 搬到 weights 之後），把 DMA 壓到頻寬地板。
