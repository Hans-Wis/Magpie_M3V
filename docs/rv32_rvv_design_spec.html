低功耗 RV32 + RVV 向量核心設計規格

本文件參考 Google Coral NPU（開源、超低功耗神經處理單元，基於 32-bit RISC-V ISA） 之公開資料進行整理與延伸，作為 Claude Code 在實作 RV32 純量核心與 RVV 向量擴充時應遵循的 設計規格書。內容涵蓋 ISA 定義、微架構、記憶體 / 匯流排介面、CSR 規格與驗證策略。

RV32IM + F + Zve32x 4-stage · in-order dispatch / OoO retire 4-way scalar / 2-way vector dispatch 128-bit SIMD datapath AXI4 master/slave ITCM 8KB / DTCM 32KB
01

設計目標與範疇

此核心目標為在穿戴式裝置（耳機、AR 眼鏡、智慧手錶）等超低功耗場景下，提供一顆 「可用標準工具鏈編譯、又具備 ML 推論所需資料路徑效率」的 C-programmable 加速器， 在通用可程式性與領域專用效率之間取得平衡（此為 Coral NPU 的核心設計哲學）。

設計目標

  • 能效優先：降低純量控制流的 overhead，並縮短資料在記憶體階層中的搬移距離。
  • 標準工具鏈相容：以 RISC-V 標準擴充（I/M/F/Zve32x/Zicsr/Zifencei/Zbb）為基礎，可用 GCC/LLVM 直接編譯 C/C++。
  • 向量化 ML 運算：透過 RVV（Zve32x）子集提供 8/16/32-bit 資料寬度的 SIMD 運算，滿足 int8/int16 量化推論需求。
  • 可整合性：以 AXI4 作為 SoC 週邊介面（同時具備 master 與 slave 角色），可被外部 host CPU 配置與除錯（GDB）。
  • 確定性延遲：ITCM / DTCM 採用 single-cycle SRAM 而非快取，避免快取失誤造成的不確定延遲。
Claude Code 實作原則 實作時請將「純量核心 (scalar)」「向量核心 (rvv)」「矩陣核心 (matrix，選配)」視為三個可獨立驗證的子系統， 透過明確定義的 command queue / scoreboard 介面耦合，而非緊密糾纏的單一大型模組。任何新增指令或資料通路， 都應先更新本規格書對應章節，再落地為程式碼與測試。
02

ISA 規格

完整 RISC-V ISA 標籤：rv32imf_zve32x_zicsr_zifencei_zbb

擴充模組定義
擴充說明
I基礎 32-bit 整數指令集（Base Integer ISA）
M整數乘法 / 除法標準擴充
F單精度浮點運算標準擴充
Zve32xRISC-V Vector（V）擴充之嵌入式處理器子集 — 32-bit 元素寬度、整數運算為主，不要求完整 V 擴充所有功能
Zicsr控制與狀態暫存器（CSR）存取指令
Zifencei指令快取一致性 fence 指令
Zbb基本位元操作（bit-manipulation）標準擴充

暫存器檔案

純量暫存器

31 個 32-bit 通用暫存器 x1–x31，x0 硬接地為 0。位址空間 32-bit，適用於應用程式與作業系統核心。

向量暫存器

32 個 256-bit 向量暫存器 v0–v31，支援 8/16/32-bit 元素寬度切分（例如 int32 × 8 lane）。

支援之資料型別：int8、int16（int32 累加）；浮點資料型別支援規劃於未來版本。 向量與矩陣的自訂運算功能，將隨未來 RISC-V 標準底定而逐步遷移對齊。

04

管線微架構

四級管線，指令依序分派（in-order dispatch）、允許非依序完成（out-of-order retire）。 純量指令支援四路分派，向量指令支援兩路分派。

圖 4.1 — 四級管線示意圖（依序分派、非依序完成，多執行單元並行）

Hazard 與流程控制

  • Hazard 偵測涵蓋 RAW（Read-After-Write）、WAR（Write-After-Read）、WAW（Write-After-Write）。
  • Pipeline stall / flush 機制需支援分支誤判、例外進入時的管線清空。
  • Instruction scoreboard 需同時追蹤純量與向量指令的完成狀態，因為 LSU 為共用資源。
Claude Code 實作原則 Scoreboard 與 dispatch 邏輯應設計為獨立、可單元測試的模組（見第 12 章佈局），並針對 RAW/WAR/WAW 三類情境各自撰寫方向性測試（directed test）與隨機測試（random test）， 避免僅以整合測試覆蓋 hazard 邏輯。
05

純量核心規格

RV32IM 前端，驅動 ML 與 SIMD 後端的 command queue。

純量核心特性
暫存器31 個 32-bit 通用暫存器 x1–x31，x0 恆為 0
算術指令加、減、乘、除等（依 RV32IM 定義）
訪存指令支援立即值、暫存器、索引等定址模式的 load/store
分支指令BEQ, BNE, BLT, BGE, JAL, JALR 等
中斷處理純量核心負責中斷進入 / 返回流程
CSR依 rv32_Zicsr 規格，per-hart 4096 個暫存器位址空間

CSR 存取指令

CSRRW / CSRRS / CSRRC原子讀取並寫入 / 設定位元 / 清除位元
CSRRWI / CSRRSI / CSRRCI對應之立即值版本
CSRR / CSRW / CSRS / CSRC組譯器 pseudo-instruction，簡化常見操作

CSR 位址編碼慣例：csr[11:10] 表示讀寫屬性（00/01/10 為可讀寫，11 為唯讀）， csr[9:8] 表示可存取之最低特權等級。

06

向量執行引擎（RVV）規格

依循 RISC-V Vector 標準的 Zve32x 嵌入式子集，提供適合 ML 推論之 SIMD 資料路徑。

圖 6.1 — 向量暫存器依 SEW 切分示意圖

向量執行引擎特性
向量暫存器v0–v31，共 32 個，每個 256-bit
資料寬度8 / 16 / 32-bit（SEW 可設定）
運算資料路徑128-bit SIMD pipeline（256-bit 為未來規劃）
累加器8×8×32-bit accumulator，記為 acc<8><8>
分派頻寬2-way vector dispatch
資料型別int8、int16（int32 累加），浮點規劃中
Claude Code 實作原則 向量核心與純量核心之間僅透過 command queue 介面耦合（純量前端解碼向量指令後推入佇列， 向量引擎非同步消耗）。實作時避免讓向量執行單元直接讀取純量 decode 狀態，以保持兩者可獨立驗證、 未來可替換為不同微架構（例如 128-bit → 256-bit 升級）而不影響純量核心。
07

矩陣執行引擎（選配）

量化外積乘加（outer-product MAC）引擎，用於加速矩陣乘法密集之 ML 運算（如卷積、全連接層）。

運算模式Quantized outer-product multiply-accumulate
乘法單元4 × 8-bit 乘法，歸約至 32-bit 累加器
吞吐量256 MACs / cycle
資料型別int8（量化）

矩陣引擎為架構上的選配子系統：若目標應用（如純姿態估測、輕量分類）不需要矩陣乘法加速， 可先以純量 + 向量核心完成 MVP，再視效能需求決定是否導入矩陣引擎。

08

記憶體子系統

採 tightly-coupled memory（TCM）而非快取，確保單週期存取延遲與可預測時序， 適合即時性要求高的推論工作負載。

圖 8.1 — 記憶體階層與存取路徑

  • ITCM 與 DTCM 皆為單週期延遲 SRAM，效率優於快取記憶體（無 miss penalty）。
  • LSU 透過 IBUS / DBUS / EBUS 三組匯流排存取 ITCM、DTCM 與外部記憶體。
  • 支援 byte / half-word / word 三種資料存取粒度，以及多種 burst 模式與長度。
  • 需正確處理 WRESP（write response）與 RDATA（read data）之 back-pressure。
09

AXI4 匯流排介面

核心以 AXI4（AMBA 標準）作為對外週邊介面，同時扮演 master（存取外部記憶體）與 slave（供 host 處理器配置 / 除錯核心）角色。

AXI4 通道
AWWrite address channel
WWrite data channel
BWrite response channel
ARRead address channel
RRead data channel
  • 需支援位址合法性與對齊（address validity / alignment）檢查。
  • 需支援 ready/valid 交握協定與 INCR / FIXED burst 交易模式。
  • 需具備錯誤訊號回報（error signaling）機制。
  • 作為 slave 時，需支援 host 透過 AXI4 讀寫本核心之自訂 CSR（見第 10 章）。
10

CSR 規格

除標準 RISC-V Zicsr CSR 外，核心額外定義三個自訂 CSR，供外部 host 處理器透過 AXI4 slave 介面存取， 用於核心重置、啟動位址設定與狀態查詢。

自訂 CSR：RESET_CONTROL（offset 0x0）
Bits名稱說明存取重置值
0RESET1 = 核心處於 reset 狀態；0 = 非 resetR/W1
1CLOCK_GATE1 = 時脈閘控中；0 = 時脈運行中R/W1
31:2RESERVED保留，寫入忽略，讀取為 0R0

啟動順序：上電後核心處於 reset 且時脈閘控。啟動流程須先釋放 CLOCK_GATE， 再解除 RESET。

自訂 CSR：PC_START（offset 0x4）
Bits名稱說明存取重置值
31:0START_ADDRESS核心開始執行的位址。須於解除 reset 前設定。R/W0
自訂 CSR：STATUS（offset 0x8，唯讀）
Bits名稱說明存取重置值
0HALTED1 = 核心已停止（例如執行 mpause 後）R0
1FAULT1 = 核心發生錯誤R0
31:2RESERVED保留，讀取為 0R0

標準 RISC-V CSR（Zicsr）

  • 每個 hart 擁有獨立位址空間，最多 4096 個暫存器。
  • CSR 位址高 4 位元 csr[11:8] 依慣例編碼讀寫權限與最低可存取特權等級。
  • 特權架構相關 CSR 供作業系統 / hypervisor 管理系統、處理中斷、控制硬體功能；非特權指令則可存取效能計數器、計時器、浮點狀態暫存器等子集。
11

例外與中斷處理

  • 需實作例外偵測與處理流程：進入 / 返回序列、cause 記錄、優先權排序。
  • 純量核心負責中斷之接收與分派；向量 / 矩陣引擎之運算錯誤需回報至純量核心的例外邏輯。
  • 建議 cause 編碼遵循 RISC-V Privileged 規範，並保留自訂錯誤碼區段供向量 / 矩陣引擎專用例外使用。
12

程式碼佈局規範

全案 RTL 一律使用 (System)Verilog 撰寫，不使用 Chisel / Scala。 Claude Code 進行實作時，請依下列目錄結構組織程式碼： 

rtl/
├── scalar/          // RV32 純量核心：fetch/decode/dispatch、ALU/Mul/Div、暫存器檔、CSR
├── vector/          // RVV 向量核心：向量暫存器檔、SIMD ALU、command queue 介面
├── matrix/          // 矩陣引擎（選配）：outer-product MAC array
└── soc/             // 頂層整合：三引擎耦合、LSU、TCM 記憶體、AXI4 介面

dv/                  // Design Verification：功能性 testbench（cocotb + Verilog DUT）
├── scalar/          // 純量核心測試（含 RAW/WAR/WAW hazard 測試）
├── vector/          // 向量核心測試（依 SEW 8/16/32 分類）
└── bus/             // AXI4 master/slave 整合測試

lint/
├── verilator/       // Verilator lint 規則與 waiver 清單
└── spyglass/        // Synopsys SpyGlass lint / CDC 規則與 waiver 清單

tests/
└── gate/            // Python 撰寫之 gate-level 測試（post-synthesis netlist）

sw/
└── benchmark/       // LLM / ML 測試工作負載（見下方 Benchmark 套件）

sim/
├── verilator/       // 開源模擬，開發階段快速迭代
└── vcs/             // Synopsys VCS 模擬，正式回歸測試

synth/
└── dc/              // Synopsys Design Compiler 合成腳本與 timing constraints

命名與模組邊界原則

  • 純量 / 向量 / 矩陣三引擎各自為獨立 Verilog 模組（分別置於 rtl/scalar、rtl/vector、rtl/matrix），僅透過 command queue 或 scoreboard 明確介面通訊，禁止跨模組直接存取內部訊號。
  • rtl/soc 僅負責頂層接線與仲裁，不得放入任何運算邏輯，以維持三引擎的獨立驗證性。
  • 自訂 CSR（RESET_CONTROL / PC_START / STATUS）獨立於標準 Zicsr CSR file，並在頂層文件中明確標示其為「非 RISC-V 標準暫存器」。
  • 任何新增的自訂指令 / CSR，需同步更新本規格書第 02、10 章與對應測試計畫。
  • lint/ 內的 waiver 清單需附上理由註解，不得無說明地全域關閉規則。

Benchmark 套件（sw/benchmark/）

用於驗證核心 ML 推論效能與正確性的代表性工作負載，涵蓋傳統 CNN 與現代小型語言模型（SLM）， 測試程式以 C/C++ 撰寫並以標準 RISC-V 工具鏈交叉編譯後於 sim/ 或實體晶片上執行。

核心 Benchmark 清單
Benchmark類型驗證重點
MobileNetCNN 影像分類int8 量化卷積、深度可分離卷積（depthwise separable conv）之向量 / 矩陣引擎吞吐量
MLPerf Tiny標準化微控制器 ML 基準套件跨工作負載（關鍵字偵測、影像分類、異常偵測等）之延遲與能效標準化評比
Gemma 3 270M小型語言模型（SLM）int8/int16 量化矩陣乘法密集運算、KV cache 存取模式對 DTCM 頻寬的壓力測試

Claude Code 實作原則 四項 benchmark 應各自可獨立編譯、獨立執行、獨立回報通過與否（pass/fail + 效能數據）， 並整合進 tests/gate 或 CI 回歸流程；SLM（Gemma 3 270M、SmolLM2 135M）測資請先以量化後的 int8/int16 權重驗證功能正確性，效能量測（tokens/sec、cycles/token）另立獨立報表，不與功能性 pass/fail 混雜。

驗證策略

純量核心驗證

RV32IM 指令逐一方向性測試、CSR 讀寫測試、分支 / 跳躍正確性、hazard（RAW/WAR/WAW）方向性 + 隨機測試。

向量核心驗證

依 SEW（8/16/32）分別驗證資料切分正確性、累加器溢位處理、command queue 與純量前端之交握時序。

匯流排 / 整合驗證

AXI4 master/slave 各通道之 handshake、burst、error signaling；host 透過 slave 介面存取自訂 CSR 之流程。

系統層級驗證

以 GDB 連線驗證除錯流程；以代表性 ML kernel（如 int8 卷積、姿態估測子運算）驗證端到端功能與效能。

Claude Code 實作原則 每完成一個模組（scalar / rvv / bus / csr），先撰寫對應 cocotb 測試並確認通過，再進入下一模組； 避免在缺乏單元測試覆蓋的情況下進行大範圍整合。所有測試需可於 CI 中重現執行。

14

建議實作里程碑

  1. M1 — RV32IM 純量核心：fetch/decode/dispatch、ALU/BRU/Mul-Div、暫存器檔、基本 CSR，通過 RV32IM 指令集測試。
  2. M2 — 記憶體與匯流排：ITCM/DTCM 整合、LSU、AXI4 master/slave，通過匯流排整合測試與自訂 CSR 存取測試。
  3. M3 — F 擴充與 Zicsr/Zifencei/Zbb：補齊浮點運算與其餘標準擴充。
  4. M4 — RVV（Zve32x）向量核心：向量暫存器檔、SIMD ALU、command queue 介接純量前端。
  5. M5 — 矩陣引擎（選配）：依應用需求決定是否導入，並驗證與向量核心的資料共用路徑。
  6. M6 — 系統驗證：GDB 除錯流程、代表性 ML 模型端到端驗證、功耗與時序 sign-off。
  7. M7 — Benchmark 驗收：依序跑通 MobileNet → MLPerf Tiny → Gemma 3 270M → SmolLM2 135M，記錄各項功能性 pass/fail 與效能數據（cycles、tokens/sec）作為最終驗收基準。
