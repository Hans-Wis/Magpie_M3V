# Grok W4A8 評估 — 4-bit 權重 / 8-bit activation(2026-07-10)

> 前提=DDR 牆正式報告校準數據(G2 實效 2.86 B/cyc、decode 15-30 tok/s)。CLI 存留結論段(驗證雙層架構/gate 計畫/替代路徑對照/建議路徑 Phase 0-2)。


| 層 | 權威 | 用途 |
|---|---|---|
| **L1 結構正確性** | **自建 W4 打包 + 參考 dequant→int8→int32 mat→既有 requant 的 NumPy/固定點 model，bit-exact 對 RTL** | DMA unpack、mat、CQ e2e **gate 綠燈** |
| **L2 模型品質** | 同一套 W4 權重，**相對 fp32（或相對你的 int8 基線）的 accuracy / PPL / task metric**；**不要求 bit-exact 到 TFLM int8** | 是否「能取代產品行為」；**獨立報告，不混進 lockstep gate** |

可選 L0：  
- **Unpack unit**：packed bitstream → int8 bytes，bit-exact。  
- **Mat 回歸**：把 dequant 後 int8 **注入** 舊 int8 路徑，證明 mat/requant **零回歸**（方案 a 的最大紅利）。

### Gate 計畫（具體）

1. **`gate_w4_pack_unpack`**：隨機 group、g=64/128、邊界、odd nibble、scale=0/max → NumPy bit-exact。  
2. **`gate_w4_dma_scoreboard`**（方案 a）：AXI 讀 W4 + scale → TCM int8 映像 == golden。  
3. **`gate_w4_matmul_tile`**：單 tile W4A8 → 經 dequant 契約 → 與 NumPy dequant-mat-requant bit-exact。  
4. **`gate_45/46` 類 mat 回歸**：int8 權重路徑 **仍 bit-exact 舊金標**（證明 engine 未毀）。  
5. **e2e 一層 / 18 層 decode smoke**：不比 TFLM int8 bit；比 **L1 golden**；另跑 **L2 accuracy 腳本**（可 nightly，非每次 RTL commit 必綠若太慢）。  
6. **Green-wash 守衛**：禁止用「和 int8 TFLM 差不多」當 gate；禁止在 TB 裡軟 dequant 假裝 RTL 做了。

**Golden 所有權**：repo 內 **PTQ 導出器 + pack 格式 SSOT + NumPy 參考**（無訓練）；TFLM int8 仍是 **A8 與舊模型** 的權威，**不是 W4 權重的 bit 權威**。

## 5. 對照替代路徑：誰最便宜摸到 50+

團隊畫像：**RTL+驗證強、engine/DMA 已證、無訓練、只做 PTQ**。

| 路徑 | 對 tok/s | 工程成本 | 風險 | 估性價比 |
|---|---|---|---|---|
| **W4 + DMA unpack (a) + burst 優化** | G2→~30；stream→~45–50 | 中（DMA+格式+雙層 golden） | 精度；burst 是否真達 4.63 | **高** |
| **熱層 weight residency**（ITCM/DTCM/shared 能塞幾層就常駐幾層） | 每常駐一層省 2.25–4.5MB/token | 中（調度/映射/CQ；RTL 可能很少） | 容量算計；軟體複雜 | **極高**（常比純 quant 便宜） |
| **Wider DRAM x32** | 理論 ×2 BW → W8 也可 ~30–50 | **板級/PHY/控制器/時序**，非純 RTL 小改 | 硬體改版、schedule 長 | 有效但 **貴且慢** |
| **Layer fusion** | 減 act 往返；decode 主牆是 **weight stream**，fusion 幫有限 | 中–高（編譯/CQ/kernel） | 對 **權重牆** ROI 低 | **decode 50 非首選** |
| **W4 + TCM int4 (b)** | 同上 + 更多 residency 空間 | 高（engine） | 回歸面大 | 第二期 |
| **僅 RVV W4 (c)** | PoC 吞吐差 | 低 | 達不到 50 | 只探路 |

**粗算組合（達 50–60 的最低成本組合）**：

1. **Residency**：假設 shared/TCM 能常駐 **K 層** int8 或 W4。  
   - 全 stream 81MB → 若常駐一半層：~40MB → G2 已 ~32 tok/s 級。  
   - **W4 全 stream 42MB + 常駐 1/3 層**：有效 ~28MB → G2 **~45+**；再加 burst → **50–60**。  
2. **x32**：W8 不改模型就可能夠，但 **系統成本通常高於「DMA W4 + 軟體 residency」**。  
3. **Fusion**：優先服務 prefill/act-heavy，**不是**這條 decode 權重牆的第一刀。

## 6. 建議路徑（具體、可執行）

### Phase 0 — 一週內、零或近零 RTL  
- 用 NumPy：**對稱 W4 g=64 PTQ**（從現有 int8 或 fp32 權重）+ dequant-mat 模擬。  
- 報兩件事：**(i) 相對 int8/fp32 的 L2 精度；(ii) 42MB/token 的 tok/s 上界表**（G2 / stream）。  
- 用 **RVV (c)** 或 host 側 unpack 跑 **功能 smoke**（不追求 tok/s）。  
- **Go/No-Go**：L2 可接受 → 進 Phase 1；不可接受 → g=32 或放棄 W4 改 residency/x32。

### Phase 1 — 生產主路徑（架構確認 → ADR → 再 RTL）  
- **格式 SSOT**：packed int4（建議 2×nibble/byte，little-endian nibble 序寫死）+ **分離 per-group s16 scale 表**，g=64，對稱。  
- **(a) npu_dma on-the-fly unpack → TCM int8**；mat_engine / requant **凍結不動**。  
- Descriptor：`W4_DEQUANT`、`scale_tcm_addr`、`group=64`。  
- Gate：§4 的 L1 bit-exact + 舊 int8 mat 零回歸。  
- **同時做軟體 weight residency**（熱層 / 輪換）：這是摸 **穩 50** 的便宜槓桿，且多半 **少動 RTL**。  
- Burst：針對 W4 連續 blob **重做 tile DMA 長度**，目標有效 B/cyc **從 2.86 → ≥4.0**（否則 W4 浪費在 efficiency）。

### Phase 2 — 僅在 Phase 1 後仍 <50 或 TCM 壓力大  
- 評估 **(b) TCM int4** 以換更多 residency，或  
- **板級 x32**（若產品本來要改版）。  
- **不要**先做引擎內 group-scale MAC。

### 明確不做（第一期）  
- 動 mat_engine requant 鏈把 group scale fold 進 SRDHM。  
- 宣稱 bit-exact TFLM int8。  
- 只靠 fusion 衝 decode 50。  
- 無 L2 eval 就上 W4 當「取代 Coral 的品質宣稱」。

---

## 7. 一句推薦

**做 W4A8，但定位是「權重流量減半 + 保持 int8 引擎契約」：DMA 上 dequant（a）、對稱 g=64、scale 分離表、NumPy L1 bit-exact + 獨立 L2 accuracy；並聯熱層 residency 與 burst 拉到接近 4.63 B/cyc。**  

單獨 W4@G2 ≈ **30 tok/s 級**；**W4 + burst + 部分 residency** 才是 **50–60 的最便宜路徑**。x32 有效但更貴；fusion 對這條牆 ROI 低；**(b) 留到 residency 真缺 TCM 再動 engine。**
