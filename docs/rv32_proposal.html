02

AI Design IDE 運作架構

整套流程是一個「規格為權威 → AI 設計 → 工具驗證 → 證據入庫 → IDE 審查 → 客戶簽核」的閉環。Claude 與 Codex 不是「直接宣稱完成」，而是產生可被工具客觀驗證、可被客戶在 AI Design IDE 中逐項檢視的證據；任何缺陷由審查端回饋，回到設計迴圈修正後重跑。

合格規則：每兩階段之間都是一道 gate。Gate 只有在「對應的 flow/state 記錄與 log 實際存在且通過審查」時才算 PASS——這是整個 IDE 與本 proposal 的核心保證。
03

參考基線與合法引用邊界

本案參考 ~/project/lab/CPU/Ch2 既有 CPU lab、Claude Code CPU 實驗與相關 open-source RISC-V 專案的分階段 DV、RTL 與架構經驗：DV_TRACE／RVFI-lite commit trace、directed ISA bring-up、Spike ISS lockstep、Google RISC-V DV constrained random、exception/CSR/IRQ closure 與 sign-off report。

參考原則：RISC-V spec 是架構契約；既有內部設計、Claude Code 開發成果與 open-source CPU/tools 可作為合法參考，用來避開已知設計與驗證錯誤。若參考內容影響決策或實作，需記錄 provenance、license 約束與 Magpie_M1 自身驗證證據；C/A 等 roadmap scope 必須各自進 ADR。

04

Magpie_M1 微架構（v1 multi-cycle FSM）

v1 目標微架構為 in-order multi-cycle FSM，支援 RV32I/M 與 Zicsr。v1 沒有 pipeline stage，因此 hazard / forwarding / flush / wrong-path suppression 不適用。RVC/RV32A 與 pipelined microarchitecture 為 roadmap。下圖僅保留為未來 pipeline 參考視圖；實際 v1 RTL hierarchy 以 IP/cpu_m1/rtl 與 ip.json 為準。
