00

概觀

本規劃描述一個雙核 SoC:RV32IMC 主機負責應用邏輯與排程,RV32-based NPU 負責 ML 推論。兩者以 AXI4 解耦——主機透過記憶體映射暫存器設定與觸發 NPU,NPU 以自己的 DMA 主埠讀寫共享記憶體。

NPU 的內部結構參考 Coral NPU:它反轉傳統處理器設計,以矩陣引擎為中心,scalar 核退居控制前端角色。三個運算元件——scalar(控制)、vector(標準 RVV / Zve32x)、matrix(自訂 outer-product MAC)——由 scalar 核透過 command queue 驅動。Coral 的公開目標數字為 512 GOP/s @ 256 MAC/cycle、~6 mW @ 800 MHz–1 GHz(22 nm),本設計以此為 datapath 參考基準。

關鍵解耦：主機的 RV32IMC 與 NPU 內部的 scalar 控制核是兩顆不同的 RV32 核。前者跑應用(可含壓縮指令 C),後者是無中斷的 run-to-completion executor,只負責把工作餵進向量/矩陣後端。AXI 是它們唯一的契約面。
01

系統架構

AXI4 crossbar 居中,掛三個 agent:主機(manager)、NPU(既是 subordinate 供設定、也是 manager 供 DMA)、共享記憶體(subordinate)。控制路徑走 AXI-Lite(暫存器/doorbell),資料路徑走 AXI-Full(突發 DMA)。NPU 完成後以中斷線回報主機。

02

NPU 微架構

NPU 內部是「scalar 前端當控制器,驅動向量/矩陣後端 command queue」。scalar 核以 in-order dispatch + scoreboard 取指、解算位址、發 command;command queue 用 FIFO 與後端解耦,dependency 解除才 post。矩陣引擎是主算力:量化 outer-product,4× int8 乘積 reduce 進 32-bit accumulator。

設計取捨：scalar 前端刻意保持最小(run-to-completion、無 speculation),把面積與功耗預算讓給矩陣陣列。這正是 Coral「反轉傳統處理器」的核心——不是造一顆強 CPU 再貼加速器,而是造一顆圍繞 MAC 陣列的控制器。
03

AXI 互連與 Offload 協定

主機與 NPU 的分工透過兩類 AXI 交易表達:控制面(AXI-Lite,主機寫 NPU 暫存器)與資料面(AXI-Full,NPU 自主 DMA 突發)。offload 一次推論的協定如下:

階段發起者AXI 交易內容
SETUPHost M0Lite 寫把 model image + input tensor 佈到共享記憶體,設定 NPU 的 base 指標暫存器
DOORBELLHost M0Lite 寫寫 CTRL.START=1(doorbell),觸發 NPU scalar 核
FETCHNPU M1Full 讀scalar 核經 DMA 突發讀入 command buffer / 權重到 TCM
COMPUTENPU 內部—command queue 驅動 RVV / 矩陣引擎,accumulator 累加
WRITEBACKNPU M1Full 寫結果 tensor 突發寫回共享記憶體
DONENPUIRQ拉中斷線;主機讀 STATUS 取回結果指標
為什麼用 AXI 解耦而非緊耦合：主機與 NPU 有各自的時脈/功耗域,AXI 讓 NPU 可獨立 gating(always-on 場景下主機睡、NPU 醒)。代價是 doorbell/IRQ 的延遲,對批次張量工作可忽略;若要做細粒度 per-op 卸載,才需考慮緊耦合(如把矩陣引擎直接掛進主機的 command queue)。
04

記憶體映射

NPU 內部 TCM 為私有、single-cycle;對主機曝露的是一組控制/狀態暫存器(AXI-Lite 視窗)。共享記憶體是雙方 DMA 的交會點。

區域Base(範例)大小存取說明
NPU_CSR0x4000_00004 KBHost RW (Lite)CTRL / STATUS / base 指標 / IRQ mask
NPU_ITCM0x0000_0000*8 KBNPU 私有scalar 核指令
NPU_DTCM0x0001_0000*32 KBNPU 私有權重 / 中間 activation
SHARED_MEM0x8000_0000≤ 1 MB+Host + NPU (Full)model image · I/O tensor · command buffer

* TCM 位址為 NPU 內部視角;highmem 配置下 base 錯開至 MB 級。

05

TensorFlow → 可執行檔 編譯流程

從 Python 模型到跑在 NPU 上的 binary,有兩條互通路徑:LiteRT(TFLite)轉換器路徑,與 MLIR / IREE 路徑。兩者最終都收斂到 MLIR,經 IREE 的硬體專屬 plugin 做漸進下降(progressive lowering)——逐層把高階 tensor 語意翻譯到愈來愈接近機器碼的 dialect,最後產出目標 binary。

逐步說明

  1. 建模(Python)：TensorFlow/Keras 訓練模型(JAX、PyTorch 同理)。
    此層是純軟體,決定運算圖與精度需求。
  2. 轉 LiteRT + 量化：以 TFLiteConverter 轉成 .tflite,用 representative dataset 做 post-training int8 量化。
    量化是 NPU 效能關鍵——矩陣引擎吃 int8→int32,浮點路徑僅供 fallback。
  3. Import 到 MLIR：經 StableHLO(或由 LiteRT 轉 TOSA)進入 MLIR 世界,取得可跨 dialect 優化的中介表示。
  4. IREE + NPU plugin：硬體專屬 plugin 讓編譯器「認得」本 NPU 的 command-queue、RVV、矩陣 op;啟動 progressive lowering。
  5. Tiling / stripmine：把大 tensor op 切成符合 accumulator 尺寸與 VLEN 的區塊,產生 command queue 序列(對齊 §02 的 stripmine 機制)。
  6. Codegen：下降到 RVV + scalar 組語 dialect,經 LLVM/RV32 後端 codegen 成 code + command stream,連結成 .elf。
  7. 部署：主機把 binary 佈到 SHARED_MEM,寫 doorbell 觸發——進入 §06 的執行期資料流。
與硬體設計的接點：Tiling / stripmine → command queue 這一步,是編譯器與 §02 command-queue 硬體格式的契約面。硬體的 command 編碼一旦定案,就成為編譯器 backend 的目標 ISA;兩邊要用同一份 spec(見驗證章的單一真值原則)。
06

執行期資料流

一次推論在硬體上的生命週期,把 §03 的 offload 協定與 §02 的內部結構串起來:

  1. 主機佈資料：RV32IMC 把量化後的權重/輸入寫進 SHARED_MEM,設定 NPU 的 base 指標暫存器。
  2. Doorbell：主機寫 CTRL.START,喚醒 NPU scalar 控制核。
  3. 取 command：scalar 核經 DMA(AXI M1)突發讀入 command buffer 與權重到 TCM。
  4. 分派：command queue 驅動 RVV 向量與矩陣引擎;stripmine 把一次 dispatch 展成多筆序列化 issue。
  5. 累加：矩陣引擎做 outer-product,int8 乘積 reduce 進 32-bit accumulator;向量核處理 activation/pooling 等週邊。
  6. 寫回：結果 tensor 經 DMA 突發寫回 SHARED_MEM。
  7. 中斷：NPU 拉 IRQ;主機讀 STATUS、取回結果,或排下一個 tile。
07

驗證與簽核

兩條驗證軌,對應兩種 golden model:

子系統Golden model方法
Host RV32IMCSpike(有 ISA）RVFI lockstep + riscv-dv
NPU scalar / RVVSpike + vector（有 ISA）RVVI/RVFI lockstep · 狀態爆炸 coverage
Matrix engine無 ISA · 需自建bit-accurate 數值 ref + tensor 級容差/量化比對
AXI 互連—AXI VIP / 協定檢查 · doorbell-IRQ 時序
端到端TFLite reference整機模型推論容差比對
單一真值原則：command queue 的編碼格式必須是編譯器 backend 與 RTL 共用的同一份 spec。這份 spec 同時餵 (1) RTL 參數、(2) IREE plugin 的 codegen、(3) 矩陣引擎的數值 golden model——三邊一致才不會出現「編出來的 command 硬體不認得」的整合裂縫。雙軌 sign-off:開源軌 Verilator + cocotb,商用軌 VCS + Spyglass。
最需新建的一塊：矩陣引擎沒有 ISA golden model,那條 tensor 級數值驗證軌是本專案唯一需要從零建的驗證能力,建議由與實作隔離的獨立鏈撰寫,避免共模錯誤。
